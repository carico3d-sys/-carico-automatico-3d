## 2. FLUSSO PROPOSTO (stile EasyCargo)
## -------------------------------------

### Registrazione (Prova Gratis):
  1. Utente compila: Nome + Email + Azienda (opzionale)
  2. Clicca "Registrati"
  3. Il sistema:
     a. Crea l'account (username = email, password = generata)
     b. Genera password casuale (es: "xK9mP2qR7w")
     c. Manda email di benvenuto con:
        - "Benvenuto su Carico3D!"
        - "La tua password: xK9mP2qR7w"
        - "Accedi qui: [link]"
     d. Redirect a /workspace/
  4. L'utente apre l'email, copia la password, accede

### Login:
  ├── Google OAuth (come prima)
  └── Email + Password

### Cambio Password (dalle Impostazioni):
  1. Utente loggato → Impostazioni → "Cambia Password"
  2. Compila: Vecchia password → Nuova password → Conferma
  3. Conferma → Password aggiornata

### Reset Password (Password Dimenticata):
  1. Dalla pagina login → "Password dimenticata?"
  2. Compila: Email
  3. Ricevi email con link per reimpostare
  4. Click sul link → Nuova password


## 3. SERVIZIO EMAIL RICHIESTO
## ----------------------------

### Opzioni:

  A) SMTP del proprio provider (gratuito o incluso nell'hosting)
     - Configurabile in Django settings
     - Pro: Nessun costo extra
     - Contro: Può essere segnato come spam

  B) SendGrid (consigliato per produzione)
     - Piano gratuito: 100 email/giorno
     - API semplice
     - Pro: Alta deliverability, tracking
     - Contro: 100 email/giorno nel piano free

  C) Mailgun
     - Piano gratuito: 500 email/mese (primi 3 mesi)
     - Pro: Economico
     - Contro: Setup più complesso

  D) Amazon SES
     - Costo: $0.10 per 1000 email
     - Pro: Molto economico
     - Contro: Setup AWS richiesto

### Configurazione Django:

  # In .env
  EMAIL_HOST=smtp.gmail.com          # o smtp.sendgrid.net
  EMAIL_PORT=587
  EMAIL_USE_TLS=True
  EMAIL_HOST_USER=tua@email.com
  EMAIL_HOST_PASSWORD=xxx            # App password (non la password Gmail)

  # In settings.py
  DEFAULT_FROM_EMAIL = 'Carico3D <noreply@carico3d.com>'

## 5. VIEW DA IMPLEMENTARE
## -------------------------

### 1) Registrazione con email:
  POST /api/auth/register/
  - Riceve: { email, nome, azienda (opzionale) }
  - Crea account con password generata
  - Manda email di benvenuto
  - Restituisce: { success, message }

### 2) Cambio password:
  POST /api/auth/change-password/
  - Richiede: autenticazione
  - Riceve: { old_password, new_password, confirm_password }
  - Aggiorna password
  - Restituisce: { success, message }

### 3) Reset password (richiesta):
  POST /api/auth/forgot-password/
  - Riceve: { email }
  - Genera token (valido 24h)
  - Manda email con link di reset
  - Restituisce: { success, message }

### 4) Reset password (conferma):
  POST /api/auth/reset-password/
  - Riceve: { token, new_password, confirm_password }
  - Valida token
  - Aggiorna password
  - Restituisce: { success, message }

## 8. SICUREZZA
## -------------

### Misure da implementare:

  1. Rate limiting:
     - Max 5 tentativi di login per 15 minuti (per IP)
     - Max 3 reset password per ora (per email)
     - Max 3 registrazione per ora (per IP)

  2. Token sicuri:
     - Token reset: 32 bytes casuali, hex-encoded
     - Scadenza: 24 ore
     - One-time use: il token viene cancellato dopo l'uso

  3. Password hash:
     - Django PBKDF2 (già implementato, default)

  4. Brute force protection:
     - django-axes (già implementato nel progetto)
     - Blocca dopo 5 tentativi falliti

  5. Email verification:
     - Token verifica email (opzionale per ora)
     - Da implementare in futuro se necessario

## 11. RISCHI E MITIGAZIONI
## -------------------------

  Rischio: Email finisce in spam
  Mitigazione: Configurare SPF, DKIM, DMARC nel DNS

  Rischio: Password generate deboli
  Mitigazione: Usare secrets.token_urlsafe(12) (16+ caratteri)

  Rischio: Token reset compromessi
  Mitigazione: Scadenza 24h, one-time use, HTTPS obbligatorio

  Rischio: Brute force su registrazione
  Mitigazione: Rate limiting + captcha opzionale
